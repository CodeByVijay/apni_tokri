# Apni Tokri — production database installer

Single-file schema installer for a **fresh, empty** MySQL database. It replaces the manual sequence of `database/database.sql` plus every forward migration, for **new production hosts only**.

Incremental migrations under `database/migrations/` are unchanged and remain the supported upgrade path for existing databases.

## What is included

- Full schema through **1.20.0** (subscriptions, fulfilment, inventory reservations, invoices, SEO, CMS, RBAC, notifications, reports, address map pin, etc.).
- **System / reference seed only** (from baseline + migrations), dumped from allowlisted tables:
  - `settings`, `admin_roles`, `admin_permissions`, `admin_role_permissions`, `admin_users`, `admin_user_roles`
  - `faq_categories`, `delivery_store`, `delivery_zones`, `delivery_slots`
  - `subscription_plans` (default 7/15/30 templates)
  - `cms_pages` (draft legal/placeholder pages from Stage 13)
  - `notification_templates`, `coupons` (`WELCOME10` / `SAVE50` seeded **inactive** — enable in Admin when intended)

## What is not included

- Customers, orders, payments, subscriptions, invoices, reviews, testimonials, support tickets, or other QA/demo transactional data.
- Real payment gateway secrets, SMTP passwords, SMS API keys, or encryption master keys (defaults are empty/disabled/simulate).
- Product catalogue rows — run `php scripts/seed-catalogue.php` after import if you want demo products (optional; not part of this SQL file).

## Import — phpMyAdmin

1. Create an **empty** database (utf8mb4 / utf8mb4_unicode_ci).
2. Select the database → **Import** → choose `apni_tokri_production.sql`.
3. Confirm import completes with no errors.
4. Copy `includes/config.local.php.example` → `includes/config.local.php` and set DSN credentials for this database (do not point production config at a dev database by mistake).
5. Log in to Admin and change the default password; configure payment, SMTP, SMS, and encryption settings in Admin.
6. Optional: `php scripts/seed-catalogue.php` for catalogue data.
7. Run `php scripts/verify-install.php` against the new database (with `config.local.php` targeting it).

## Import — MySQL CLI

```bash
mysql -u USER -p -e "CREATE DATABASE apni_tokri CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u USER -p apni_tokri < database/production/apni_tokri_production.sql
```

Then configure the app and verify as above.

## Regenerate this file

After adding migrations, update `production_migration_sequence()` in `scripts/build-apni-tokri-production-sql.php` to match `database/README.md` order, then:

```bash
php scripts/build-apni-tokri-production-sql.php
php scripts/validate-apni-tokri-production-sql.php
```

Build uses a **temporary** database (`apni_tokri_prod_build_*`) and drops it when finished. It does **not** modify the database named in `config.local.php`.

## Safety notes

- No `DROP TABLE` in the consolidated file (`mysqldump --skip-add-drop-table`).
- `FOREIGN_KEY_CHECKS=0` during import, restored to `1` at end (standard for ordered DDL).
- Do **not** import this file into an existing production database with live data — use incremental migrations instead.
- Do **not** run build/validate against your development database name unless you intentionally set `BUILD_TARGET_DB` (build always uses a ephemeral database name by default).
